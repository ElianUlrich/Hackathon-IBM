# Firmware Dev — Mode Rules

These rules extend the common rules for the `firmware-dev` mode.
They encode docs/PROJECT_PINPILOT.md §6 (firmware rules) and §14.3/§14.4
(PlatformIO pitfalls, display/LVGL pitfalls).

---

## Firmware Structure Rules (§6)

1. **Non-blocking main loop.** No `delay()` anywhere in `loop()`. Use `millis()` for all
   timing. Each component has its own read period checked with `millis()`.

2. **Respect min_read_interval_ms.** Read each sensor no faster than its catalog value.
   DS18B20: 750 ms. BME280: 1000 ms. BH1750: 180 ms. Soil sensor: 500 ms.

3. **One module per component.** Every component instance gets:
   - `src/components/<instance_id>.h`  — class declaration with `begin()` and `update()`
   - `src/components/<instance_id>.cpp` — implementation
   `main.cpp` only calls `begin()` once and `update()` in the loop.

4. **No magic numbers.** All GPIO numbers, I2C addresses, SPI frequencies, baud rates go in
   `include/pinmap.h`. Source files `#include "pinmap.h"` and use named constants only.
   Example: `#define PIN_SOIL_AOUT 34`, `#define ADDR_BME280 0x76`.

5. **Device presence check in every `begin()`.** I2C devices: check `Wire.begin()` ACK.
   SPI devices: check a known register. 1-Wire: call `getDeviceCount()`. Log a clear error
   to Serial if the device is missing — do not hang or crash silently.

6. **Serial at 115200 baud.** Print a startup summary in `setup()`:
   - Firmware name and source project.json name
   - List of detected devices (or "NOT FOUND" for each missing device)
   - Bus configuration (I2C pins + frequency, SPI pins + frequency, etc.)
   - Pin map summary from pinmap.h

7. **Shared Wire instance.** Call `Wire.begin(SDA_PIN, SCL_PIN)` exactly **once** in
   `setup()`, before any I2C device `begin()`. Use the pins from pinmap.h.

8. **Pinned library versions.** Every entry in `lib_deps` must use a pinned version
   (e.g. `adafruit/Adafruit BME280 Library@^2.2.4`). Read the version from the catalog
   entry's `libraries` array. Never omit versions or use `latest`.

9. **Generated file header.** Every generated `.h`, `.cpp`, `.ini`, and `.py` file starts with:
   ```
   // Generated by PinPilot. Source: project.json
   // Purpose: <one-line description of this file>
   // Do not edit manually — regenerate from project.json.
   ```

## PlatformIO / platformio.ini Rules (§14.3)

- `platform = espressif32`
- `board = esp32dev`
- `framework = arduino`
- `monitor_speed = 115200`
- All libraries in `lib_deps` with pinned versions from the catalog `libraries` array.
- Use exactly **one** library per component (the one in its catalog entry). Never mix two
  libraries for the same device.
- Classic ESP32 has ~320 KB RAM. Check and report the RAM/flash usage shown in build output.

## Display Rules (§14.4)

### OLED (SSD1306 / SH1106) — use U8g2, not LVGL
- Include `U8g2lib.h`. Use `U8G2_SSD1306_128X64_NONAME_F_HW_I2C` for SSD1306.
- Note in generated code: if the module is a 1.3-inch OLED, try `U8G2_SH1106_128X64_NONAME_F_HW_I2C`.
- Render widgets with `u8g2.clearBuffer()` / draw calls / `u8g2.sendBuffer()`.
- Use full-buffer or page-buffer constructor that fits in the available RAM.

### TFT (ILI9341 / ST7789) — use LVGL v9 + TFT_eSPI
- **LVGL version: v9 only.** Do not use v8 API symbols:
  `lv_disp_drv_t`, `lv_disp_draw_buf_t`, `lv_disp_drv_init`, `lv_disp_drv_register` are v8 and
  will not compile. Use `lv_display_create`, `lv_display_set_flush_cb`, `lv_display_set_buffers`.
- **No full-screen buffer.** 320x240 x 2 bytes = 150 KB — exceeds safe ESP32 heap allocation.
  Use a partial buffer: `static lv_color_t buf[LV_HOR_RES * 24]` (~15 KB).
- Provide LVGL tick via `lv_tick_set_cb(millis)` in setup().
- Call `lv_timer_handler()` every ~5 ms in the main loop. Never block the loop.
- Update widgets only when a new sensor value arrives, not every loop iteration.
- **TFT_eSPI configuration via build_flags only.** Required flags in platformio.ini:
  ```
  -D USER_SETUP_LOADED
  -D ILI9341_DRIVER        (or ST7789_DRIVER)
  -D TFT_MOSI=<pin>
  -D TFT_SCLK=<pin>
  -D TFT_CS=<pin>
  -D TFT_DC=<pin>
  -D TFT_RST=<pin>
  -D SPI_FREQUENCY=40000000
  ```
  Read pin values from the ILI9341 instance's `pin_mapping` in project.json
  (keys: `"MOSI"`, `"SCK"`, `"CS"`, `"DC"`, `"RESET"`).
  **Never edit any file inside `.pio/libdeps/`.**
- Provide `lv_conf.h` in the project's `include/` directory.
  Enable only the widgets and fonts actually used by `project.json`'s `screen.widgets`.
  Add `-D LV_CONF_INCLUDE_SIMPLE` to build_flags and add `include/` to `build_src_filter`.

## Subagent Strategy

When the `generate-firmware` skill is active, use **exactly two parallel subagents**:
- **Subagent A** — all sensor/actuator driver modules:
  generates `src/components/<instance_id>.h/.cpp` for every non-display component.
- **Subagent B** — display/GUI code:
  activates the `lvgl-screen` skill and generates the display driver files.

After both complete, firmware-dev assembles `pinmap.h`, `main.cpp`, and `platformio.ini`
directly (not via subagents). Then runs the build.

**Do not spawn one subagent per component** — that wastes Bobcoins.

---

## Build and Handoff

- After generating all files, run: `python scripts/build.py examples/<demo>/firmware`
- If **BUILD PASSED**: report RAM/flash usage from the build output. Declare success.
- If **BUILD FAILED**: switch to `build-fixer` mode immediately. This counts as attempt 1.
