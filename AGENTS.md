compiled PlatformIO firmware project and LaTeX documentation. Built for the IBM Bob 2.0 hackathon.
Target board: **ESP32-WROOM-32** (`esp32dev`). Full spec: `docs/PROJECT_PINPILOT.md`.

## 5. Environment Rules  (§14.1)

- **Windows 11 / PowerShell only.** No bash scripts.
- Automation → Python scripts in `scripts/` using `pathlib` and `subprocess.run([...], ...)`.
  Never pass shell strings to subprocess. Never use `&&` to chain commands.
- Run one command at a time and wait for its output before the next.
- Before Phase 1: verify tools with `node --version`, `npm --version`, `python --version`,
  `pio --version`, `pdflatex --version`. If any is missing, stop and tell the user.
- First PlatformIO build downloads the ESP32 toolchain (~hundreds of MB). Be patient.

## 6. Firmware Rules  (§6)

1. **Non-blocking loop.** No `delay()` in `loop()`. Use `millis()` scheduling.
2. Respect each sensor's `min_read_interval_ms` from the catalog.
3. One module per component: `src/components/<id>.h/.cpp` with `begin()` and `update()`.
4. All pin numbers and addresses in `include/pinmap.h`. No magic numbers.
5. Every `begin()` checks device presence and logs a clear error on `Serial` if missing.
6. `Serial` at 115 200 baud with startup summary (devices, bus config, pin map).
7. One shared `Wire` instance; one SPI bus with unique CS per device.
8. Library versions pinned in `platformio.ini` `lib_deps`.
9. Every generated file starts with a header comment: generated by PinPilot, source `project.json`.

## 7. PlatformIO / Arduino Pitfalls  (§14.3)

- `platformio.ini`: `platform = espressif32`, `board = esp32dev`, `framework = arduino`,
  `monitor_speed = 115200`, all libraries in `lib_deps` with **pinned versions**.
- One library per component (the one in its catalog entry). Never mix two for the same device.
- Call `Wire.begin(SDA, SCL)` **once**, before any I2C device `begin()`.
- Classic ESP32 has ~320 KB RAM. Check RAM/flash usage in build output and report it.

## 8. Display / LVGL Pitfalls  (§14.4)

- **LVGL v9 API only.** `lv_disp_drv_t` / `lv_disp_draw_buf_t` are v8 — will not compile.
- Put `lv_conf.h` in the project; reference it with `-D LV_CONF_INCLUDE_SIMPLE` + include path.
  Enable only the widgets and fonts actually used.
- **No full-screen buffer.** 320×240 × 2 bytes = 150 KB. Use a ~1/10-screen partial buffer.
- Call `lv_timer_handler()` every ~5 ms from the main loop; provide tick via `lv_tick_set_cb(millis)`.
- Configure TFT_eSPI **only via `build_flags`** in `platformio.ini`. Never edit files in `.pio/libdeps/`.
- OLED (SSD1306) uses **U8g2**, not LVGL.

## 9. Web App Pitfalls  (§14.5)

- Create with `npm create vite@latest web -- --template react-ts`.
- Only add packages beyond React + React Flow + Vite after asking the user.
- Load catalog and pin table from the `catalog/` JSON files at build time — never duplicate the
  validation logic in TypeScript by hand.
- No backend. Export uses a browser file download.

## 10. LaTeX Pitfalls  (§14.6)

- **Escape** `_ & % # $ { }` in all generated LaTeX. Use a Python helper function for this.
- `pdflatex` only. No `fontspec`, `minted`, XeLaTeX, LuaLaTeX, or `--shell-escape`.
- Allowed packages: `geometry`, `graphicx`, `booktabs`, `longtable`, `tikz`, `listings`,
  `xcolor`, `hyperref`, `caption`. Ask before adding others.
- Compile twice into `build/`; copy only the final PDF to `docs/`.

## 11. Security Rules  (§14.7)

- No secrets, credentials, or API keys in the repository — ever.
- WiFi credentials in generated firmware → `include/secrets.h` (gitignored).
  Commit only `include/secrets.example.h` with placeholders.

## 12. Repository Hygiene  (§14.7)

- Do not commit or push unless the user asks.
- Small commits, one per phase, conventional messages (`feat:`, `fix:`, `docs:`, `test:`).
- Never modify or delete `docs/PROJECT_PINPILOT.md` or the `bob_sessions/` directory.

## 13. Working Agreement  (§14.8)

- **Plan first.** List files to create/change and wait for approval before writing code.
- **Max 3 fix attempts** per failing build or test. Then stop, summarize errors and hypotheses, ask.
- **Never invent tool output.** Every build result or version number must come from running the command.
- **Never invent component data.** Pinouts, addresses, voltages from the datasheet/catalog only.
  Mark unknowns as `"TODO: verify"` and tell the user.
- End every phase with a short report (files created/changed, commands run, acceptance criteria met,
  open issues) and **append it to `docs/BOB_USAGE_LOG.md`**.
- **User:** capture Bob session screenshots after each phase and save them to `bob_sessions/`.
